# 周边去哪儿

使用已配置的高德 MCP，完成周边地点推荐。各地点都是从同一起点出发的独立备选。

## 1. 理解需求

提取城市、起点坐标、地点类型、步行时间上限、推荐数量和排序偏好，同时保留用户的排除条件。起点坐标使用“经度,纬度”。推荐数量默认 3 个，用户要求更少时按其要求。

## 2. 搜索候选

调用 `maps_around_search`：

- `location`：用户提供的起点坐标。
- `keywords`：地点类别或明确的品牌，如“咖啡馆”“公园”。
- `radius`：米数的字符串，如 `"2000"`；结合用户指定范围和步行需求选择。

从 `pois` 中按用户条件选取约 6–10 个候选，按 POI ID 去重。对候选调用 `maps_search_detail(id)`，获取地址、`location`、城市和类型；搜索结果已包含这些信息时可直接使用。综合名称与分类判断需求匹配度，例如名称为“咖啡餐厅”、分类为“餐饮相关”的复合门店也可作为咖啡馆候选。

结果不足时，补充一轮搜索：调整类别关键词或扩大搜索半径，保持用户的时间上限和其他条件。需要按城市查找时，可用 `maps_text_search(keywords, city)` 补充候选。

## 3. 查询步行路线

对候选调用 `maps_direction_walking`，`origin` 为用户起点，`destination` 为地点详情中的坐标。

从 `route.paths` 读取步行距离 `distance`（米）和耗时 `duration`（秒）；返回为文本 JSON 时先解析。每个地点选取一条符合偏好的有效路径，距离与耗时使用同一路径的数据。

按原始秒数筛选：例如“不超过 15 分钟”为 `duration <= 900`，“少于 15 分钟”为 `duration < 900`。步行时间以路线结果为准。单个地点路线查询失败时，继续查询其他候选。

## 4. 筛选排序

在满足地点类型、步行时间及其他明确条件的候选中排序：

- “优先近一点”：步行距离升序，再按耗时升序。
- “尽快到达”：步行耗时升序，再按距离升序。
- 未指定排序：先考虑需求匹配度，再按步行耗时排序。

取用户要求的数量，最多 3 个。安静程度、排队情况、营业状态等属性按查询依据描述；缺少依据的标注“未核实”，作为必要条件时只选择能够确认满足的地点。

## 5. 输出推荐

用一句话说明起点、时间条件和排序方式，然后以表格或列表呈现每个地点的：

**名称｜地址｜预计步行距离｜预计步行时间｜一句推荐理由**

理由结合用户需求与实际查询结果。距离用米或公里，时间用分钟，接近时间上限时展示到秒。注明步行数据来自高德路线查询。

数量不足时返回已有合格结果并简述原因；没有合适结果或查询失败时如实说明，可建议放宽时间或搜索范围。
