# 周边去哪儿

使用评测平台已配置的高德 MCP，完成“提出需求 → 查询真实地点与步行路线 → 返回推荐”。各地点都是从同一起点出发的独立备选。

## 高德 MCP 工具

使用评测环境已经配置的高德地图 MCP Server。官方 npm 包为 `@amap/amap-maps-mcp-server`，协议中的服务标识为 `mcp-server/amap-maps`；客户端配置中的服务别名由运行环境决定。

从当前可用工具中按功能和输入参数识别下列高德工具，调用环境暴露的完整工具名。若工具名带服务命名空间前缀，使用该完整名称；下表给出官方工具的原始名称。

| 能力 | 原始工具名 | 参数 |
| --- | --- | --- |
| 周边地点搜索 | `maps_around_search` | `location`（经度,纬度）、`keywords`、`radius`（米数字符串） |
| POI 详情 | `maps_search_detail` | `id`（搜索返回的 POI ID） |
| 步行路线 | `maps_direction_walking` | `origin`、`destination`（均为经度,纬度） |
| 城市关键词搜索 | `maps_text_search` | `keywords`、`city` |

工具参数按其实际输入 schema 组成 JSON 对象，例如周边搜索使用 `{"location":"120.164052,30.254642","keywords":"咖啡馆","radius":"2000"}`，详情查询使用 `{"id":"搜索结果中的真实 POI ID"}`。示例起点仅说明格式，执行时使用用户输入的起点。返回为 MCP `content` 文本块时，解析其中的 JSON，再读取 POI 或路线数据。

## 1. 理解需求

从用户输入中提取以下字段：

| 字段 | 含义 |
| --- | --- |
| `city` | 城市，用于核对地点及补充搜索 |
| `origin` | 起点坐标，格式为“经度,纬度”；评测会直接提供 |
| `keywords` | 地点类型、品牌或用户明确的搜索关键词 |
| `walk_limit` | 步行时间或距离上限，以及“不超过”“少于”等边界条件 |
| `max_n` | 推荐数量，默认 3 个，上限 3 个；用户要求更少时按其要求 |
| `sort_pref` | 距离、耗时等排序偏好 |

将地点类型、时间或距离上限、排除条件等硬条件用于筛选，将软偏好用于排序和推荐理由。执行时始终使用用户提供的起点，不替换为示例坐标。

## 2. 搜索候选

调用 `maps_around_search`：

- `location`：用户提供的起点坐标。
- `keywords`：地点类别或明确的品牌，如“咖啡馆”“公园”。
- `radius`：米数的字符串，如 `"2000"`；结合用户指定范围和步行需求选择。

从 `pois` 中按用户条件选取约 6–10 个候选，按 POI ID 去重。候选缺少坐标、地址或类型时，调用 `maps_search_detail`，传入搜索返回的真实 `id`，获取地址、`location`、城市和类型；已有信息可直接使用。取得有效终点坐标后再规划步行路线。综合名称与分类判断需求匹配度，例如名称为“咖啡餐厅”、分类为“餐饮相关”的复合门店也可作为咖啡馆候选；类型不符的地点不作为合格结果。

结果不足时，补充一轮搜索：调整类别关键词或扩大搜索半径，保持用户的时间上限和其他条件。需要按城市查找时，可用 `maps_text_search(keywords, city)` 补充候选。

## 3. 查询步行路线

对候选调用 `maps_direction_walking`，`origin` 为用户起点，`destination` 为地点详情中的坐标。

从 `route.paths` 读取步行距离 `distance`（米）和耗时 `duration`（秒）；返回为文本 JSON 时先解析。每个地点选取一条符合偏好的有效路径，距离与耗时使用同一路径的数据。

按原始秒数筛选：例如“不超过 15 分钟”为 `duration <= 900`，“少于 15 分钟”为 `duration < 900`。用户限制步行距离时，按原始米数筛选。先判断是否达标，再转换显示单位；步行距离与时间均来自步行路径规划，不能用直线距离、距离测量工具或经验估算替代。单个地点路线查询失败时，继续查询其他候选；没有取得有效步行距离与时间的地点不列为合格推荐。

## 4. 筛选排序

在满足地点类型、步行时间及其他明确条件的候选中排序：

- “优先近一点”：步行距离升序，再按耗时升序。
- “尽快到达”：步行耗时升序，再按距离升序。
- 未指定排序：先考虑需求匹配度，再按步行耗时排序。

取用户要求的数量，最多 3 个。安静程度、排队情况、营业状态等属性按查询依据描述；缺少依据的标注“未核实”，作为必要条件时只选择能够确认满足的地点。

## 5. 输出推荐

用一句话说明起点、时间或距离条件和排序方式，然后用表格呈现结果：

| 名称 | 地址 | 预计步行距离 | 预计步行时间 | 推荐理由 |
| --- | --- | --- | --- | --- |
| 工具返回的真实名称 | 工具返回的地址 | 路线距离 | 路线耗时 | 结合需求与查询依据的一句话 |

也可使用包含同样五项信息的列表。

理由结合用户需求与实际查询结果。距离用米或公里，时间用分钟，接近时间上限时展示到秒。注明步行数据来自高德路线查询。

按实际查询情况补充说明：

- **结果不足**：返回已有合格结果，说明“本次查询找到 N 个符合条件的地点，少于请求的 M 个”，概述已尝试的范围及限制，可建议放宽时间或搜索范围。
- **没有合格结果**：说明本次查询的关键词、范围及未满足的条件；实际核验过路线时，可说明核验数量。只描述已执行的查询。
- **工具失败**：简述失败的查询环节；已有经过核验的结果可照常返回，并说明其余候选未能完成核验。没有有效结果时说明暂时无法推荐，并建议稍后重试。

回答前核对：数量不超过用户要求且最多 3 个；每个结果均满足硬条件、来自同一起点并有有效步行路线；排序与路线数据一致；五项信息齐全；未核实属性及查询失败情况已说明。
