# 一页技术说明

本系统将开发任务拆成资料检索、状态恢复、模型修改、测试验证四步。样例为订单列表增加状态筛选，含一次退款状态规格更新；初始函数可运行，目标行为尚未实现，既有客户筛选与分页行为已有回归保护。

**seekdb 工程资料库。** `sdd_context.Materials` 将规格、Python 代码、测试和数据写入 `sdd_materials`，以 `(project_id, path)` 为主键，记录正文与 SHA-256。重新导入在一个事务中替换当前项目资料，不影响其他项目。查询将任务的英文词项/标识符作为绑定参数，在数据库中按正文和路径命中数量排序；SQL 返回的正文直接成为上下文。输出附来源行号与哈希，读取时对照文件，陈旧索引必须重新导入。规格不是预置答案；集成测试另验证查询变化、规格更新、删除、项目隔离与导入失败。

**PowerContext 状态。** 使用官方 Python SDK `open_builtin_runtime`、Scope 和 Memory API。状态通过 `remember` 保存完成事项、待办与真实测试结果；新进程重开 SQLite 持久化 Runtime 后用 FTS `search` 读取。业务状态没有存入自建 JSON 数据库；本地 `scope.json` 只定位 SDK Scope。恢复出的 `todo[0]` 决定 `next_action`：生成前为调用 MiniMax，验证后变为交付审阅。每次 CLI 单独运行，写入和读取的 PID 不同，并核对状态内容一致。

**MiniMax 改码。** 将数据库中检索到的有效规格、原始函数、冻结的测试及 PowerContext 恢复出的进展送入官方 Anthropic 兼容接口。只发送虚构业务样例，响应限定为 `orders.py` 完整内容。第一轮出现列表状态输入触发 TypeError 的错误；保持测试不变，把实际失败反馈给模型，第二轮修正类型检查。交付两轮请求、公共文本响应、usage、请求 ID 与最终代码哈希；不含认证头或私有思维链。结构检查不是通用代码沙箱，执行新输出前仍需审阅。

**验证与复现。** `run_demo.py prepare` 建立新项目和空状态，运行同一组目标/回归测试，保存基线，再导入 revision 2（ORD-004 refunded）。`generate` 实际调用 MiniMax；`verify` 应用审阅后的代码、核对测试文件哈希不变、运行测试，再从新进程恢复最终记录。`verify --recorded` 用已经交付的真实模型结果复现，不额外调用模型。修改前 13/14 项功能用例失败、10/10 回归通过；修改后 14/14 功能、10/10 回归通过；上下文集成测试 4/4 通过。

**运行边界。** 固定 PowerContext 提交与 seekdb 镜像，依赖完整锁定；无需未交付的本地资料、既有 Scope 或既有数据库行。面向小型、串行 SDD 样例，采用词项检索和显式状态序号，不提供多写者并发控制，也不将界面或代码量作为完成依据。
